# 躲避副驾驶（dodge-copilot）

玩单机肉鸽游戏时的走位助手：只看屏幕画面，认出角色和子弹、闪电、激光等危险物，预测它们的轨迹，替你躲闪。

- 按 `F8`：助手接管走位；再按一下交还。
- 接管期间你一按方向键，控制权立刻回到你手里。
- 按 `F12`：急停（松开所有键并退出）。

## 边界（请先读）

- 只用于**单机、离线**游戏，不用于任何联机、对战或排行榜模式。
- 只读屏幕像素、只模拟键盘鼠标或手柄输入；不读写游戏内存，不注入代码，不修改游戏文件，不绕过反作弊。
- 使用前请确认游戏的用户协议允许这类辅助工具。

## 先试试测试游戏

需要 Python 3.11 或更新版本。

```bash
pip install -e ".[dev]"
```

```bash
python -m dodge_copilot sim
```

打开后：

| 按键 | 作用 |
|---|---|
| 方向键 / WASD | 自己走 |
| `F8` | 助手接管 / 交还（右上角会变成橙色"助手接管中"） |
| 接管中按任意方向键 | 立刻交还给你（右上角变回绿色"玩家控制"） |
| `F12` 或关窗口 | 急停，退出 |
| `R` | 被打中后重开 |
| `F2` | 显示 / 隐藏调试画面 |
| `F3` | 显示 / 隐藏每帧耗时 |

其他选项：

```bash
python -m dodge_copilot sim --debug            # 一开始就显示调试画面
python -m dodge_copilot sim --camera follow    # 换成"镜头跟着玩家走"的模式
python -m dodge_copilot sim --record           # 录下接管期间的画面和决策
python -m dodge_copilot sim --policy random    # 让"助手"随机乱走（对比用）
```

### 调试画面怎么看

| 画面上的东西 | 意思 |
|---|---|
| 青绿色小圈 | 认出来的玩家，圈的大小就是"被打中"的范围 |
| 白圈 + 白线 | 认出来的子弹/敌人；线指向它半秒后会到的位置 |
| 灰圈 | 刚出现、还不知道往哪飞的东西 |
| 橙圈 | 判断为"会追人的"敌人 |
| 半透明红色 | 已经生效的激光、闪电 |
| 半透明黄色 | 还在预警的激光、闪电（可以趁这时穿过去，但不能停在上面） |
| 蓝→红的底色 | 站着不动时各处有多危险，越红越危险 |
| 青色箭头和点线 | 助手这一下选的方向，和它预计接下来走的路线 |

左下角是每帧各环节耗时（capture 截屏 / perceive 识别 / decide 决策 / act 输入）。

### 录制

加 `--record`（或在配置里写 `debug: {record: true}`）后，每次接管都会在 `recordings/<日期-时间>/` 下存一份：每帧一张带调试标注的图片，加一个 `decisions.jsonl`（每帧的时间、玩家位置、选的方向、看到几个危险物、各环节耗时）。用来复盘"这一下为什么没躲开"。`recordings/` 不会进 git。

## 存活时间（衡量助手好坏的主要数字）

同一组随机种子（0–19），测试游戏默认难度，每局最多 60 秒：

```bash
python -m dodge_copilot bench --seeds 20 --policies idle,random
```

| 策略 | 局数 | 平均存活（秒） | 中位数 | 最短 | 最长 |
|---|---|---|---|---|---|
| 不操作（idle） | 20 | 3.88 | 3.76 | 2.30 | 5.63 |
| 随机乱走（random） | 20 | 4.65 | 4.28 | 2.20 | 8.75 |
| 助手接管 | — | M1 补上 | | | |

测试游戏越往后子弹越密。开发时用一个"能偷看游戏内部状态"的验证脚本试过，默认难度下是可以一直躲开的，所以这个难度是合理的。

## 给游戏写配置

每个游戏一份 `profiles/<名字>.yaml`。仓库里有两份：

- `profiles/testgame.yaml`：测试游戏用。
- `profiles/example.yaml`：示例，每一项都有注释。只想自己用、不想进 git 的配置，命名为 `profiles/local_<名字>.yaml`。

主要内容：截屏区域、玩家怎么找（固定在画面中心 / 按颜色 / 按截图）、危险物颜色和大小、要忽略的界面区域（血条、分数、小地图）、键位、角色移动速度、热键。

配置写错（字段名拼错、类型不对）时程序会直接告诉你是哪一项，不会悄悄忽略。

`takeover.auto_resume_after_s`：你按方向键抢回控制后，默认**不会**自动恢复接管，要再按 `F8`。如果想"松手 1 秒后自动交回给助手"，把它设成 `1.0`。

### 躲闪相关的参数（一般不用动）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `hazards.min_brightness` / `min_saturation` | 170 / 90 | 多亮、多鲜艳的东西算危险物。危险物没被圈出来就调低，背景被误认就调高 |
| `hazards.line_min_brightness` / `line_min_saturation` | 100 / 70 | 激光、闪电的预警线一般暗一些，用这组更低的门槛找"细长的线" |
| `hazards.telegraph_delay_s` | 0.3 | 预警线最少多久后变成真激光。看到预警时，助手允许在这之前穿过去 |
| `hazards.motion_compensation` | false | 镜头跟着玩家走的游戏要设成 true |
| `predict.horizon_s` | 0.5 | 往前看多少秒 |
| `predict.safety_margin_px` | 4 | 至少离危险物多远（像素） |
| `predict.inertia` | 0.2 | 换方向的代价；觉得助手来回抖就调大 |
| `predict.latency_s` | 0 | 从截屏到游戏收到按键大约多久（秒），助手会往前多推算这么久 |

这些默认值是在测试游戏上做对比实验调出来的（见下面"助手怎么躲"）。

## 助手怎么躲

每一帧：

1. **找玩家**：按颜色找，或者镜头跟随的游戏直接认为玩家在画面正中。
2. **找危险物**：又亮又鲜艳、大小适中的色块当成子弹或敌人；又细又长或者很大的当成激光、闪电这类"区域"。较暗的细长线当成"预警"。血条等界面区域在配置里框出来，直接忽略。
3. **追踪**：把这一帧的每个子弹和上一帧对上，估计它往哪飞、多快。镜头跟随时先算出整个画面平移了多少。
4. **挑走法**：候选走法是"先往一个方向走 0.2 秒，再往另一个方向走"，方向有不动加 8 个方向，一共 81 种。把每种走法和每个危险物的预测轨迹对一遍，越近扣分越多，撞上扣大分；再加上"别靠墙和角落"、"别来回换方向"。选扣分最少的，只执行第一步，下一帧重新算。

试过但没用上的：把"追人的敌人"按"直奔玩家"来预测。对比实验里它反而让存活时间从 32 秒掉到 27 秒（太悲观，助手会慌），所以默认关掉了（`predict.pursuit_model`）。

## 安全措施

- 交还、急停时，助手先松开它按着的所有键。
- 程序崩溃、被 Ctrl+C、被结束进程、关掉控制台窗口时，也会先松开所有键（`try/finally`、退出钩子、信号处理三道保险）。
- 切换延迟远低于 50 毫秒（只是改一个状态、松几个键）。

## 开发者看这里

```
dodge_copilot/
  config.py        配置文件格式和严格检查
  control.py       接管 / 交还 / 急停状态机（线程安全）
  inputs.py        方向 -> 按键或摇杆；记住按了什么，能全部松开
  safety.py        崩溃、退出时松键
  loop.py          一帧：截屏 -> 识别 -> 决策 -> 输入
  perception/      看懂画面：player.py 找玩家，hazards.py 找危险物和画面平移，tracker.py 追踪
  dodge.py         预测和躲闪
  policy.py        基准策略（不操作 / 随机乱走）和策略入口
  debug.py         调试画面
  record.py        录制
  stats.py         每帧耗时统计
  bench.py         存活时间基准
  app.py           测试模式的交互窗口
  io/sim.py        测试模式接口：直接对接测试游戏
testgame/          测试用弹幕小游戏：直线、扇形、追踪弹，追人的敌人，激光，闪电；固定随机种子
tests/             单元测试：python -m pytest
```

- 测试游戏的画面用 OpenCV 画成图片，不开窗口也能跑，所以基准和测试可以在没有显示器的机器上跑。交互窗口才用 pygame。
- 测试游戏支持两种镜头：`fixed`（固定场地，有墙）和 `follow`（镜头跟着玩家，玩家永远在中间），在 `profiles/testgame.yaml` 的 `sim.camera` 里改。
- 测试游戏里的"血条"故意用了和子弹很像的红色，用来检验"忽略区"是否生效。
